reshape4intervals_wtst(ds: xarray.Dataset, granularity: int, interval: int, offset: int = 0) → xarray.Dataset[source]#

Wrapper for reshape4intervals() to reshape a dataset into intervals, additionally handling local time conversion and producing interval duplicates for summer and winter time.

Parameters:

  • ds (xarray.Dataset) – dataset with a valid time dimension to be reshaped. Must contain one constant time resolution

  • granularity (int) – time in hours in between two consecutive interval starts

  • interval (int) – time in hours of interval duration

  • offset (int, optional) – time in hours by which interval starts should be shifted from 00:00 am. E.g. if 6, intervals include the one starting at 6am (4 and 5 am UTC)

Returns:

ds_out – reshaped dataset with dimensions valid time x window. Valid time contains timestamps for respective interval, window has length of the interval and contains all timesteps belonging to the interval

Return type:

xarray.Dataset

See also

reshape4intervals(), interval_stat()

interval_stat(ds: xarray.Dataset, granularity: int, interval: int, offset: int, agg_func: collections.abc.Callable, lt_duplicates: bool = True, interp_method: grid_process.timeseries.InterpMethods | None = None, **agg_func_kwargs: Any) → xarray.Dataset[source]#

Aggregate values in time over a moving window defined by a time granularity, interval and offset. Aggregation is based on the aggregating function agg_func. The timeseries must have a granularity of maximum one hour or an interp_method must be specified for prior interpolation. The granularity does not need to be constant.

Parameters:

  • ds (xarray.Dataset) – Must have a valid time dimension, potentially with non-constant time resolution. Typical valid time dimension names are supported, and can be extended via environment variables:

    • Valid time: export GRID_PROCESS__data_model__validtime (e.g., ‘[“time”, “valid_time”, “dummy_time”]’)

    • When the coordinates variables have a CF compliant standard_name attribute, arbitrary names can be used directly.

  • granularity (int) – time in hours in between two consecutive interval starts

  • interval (int) – time in hours of interval duration

  • offset (int) – time in hours by which interval starts should be shifted from 00:00 am. E.g. if 6, intervals include the one starting after 6am

  • agg_func (callable) – specify temporal aggregation function to use. The function must operate on window dimension. E.g. agg_func = lambda x: x.mean('window')

  • lt_duplicates (bool, optional) – if True, aggregations are done in the DWH compliant style, which means intervals are calculated with respect to both UTC+1 and UTC+2. Default is True

  • interp_method (str, optional) – specify the temporal interpolation method to use if part of the timeseries has a greater time resolution than one hour. Default is no prior temporal interpolation (thus assuming the timeseries has max granularity of 1hr). Must be a method accepted by interptogranularity()

  • **agg_func_kwargs (any) – keyword arguments passed to the agg_func

Returns:

ds_out – dataset with aggregated values. Uncomplete intervals are exluded.

Return type:

xarray.Dataset

See also

reshape4intervals_wtst(), reshape4intervals(), interptogranularity()

Note

Alternatively, one can use xarray.Dataset.resample in some cases, especially when aggregating over uncomplete intervals is preferred. However, this behaviour can be problematic for cumulative aggregations (i.e. sum). Note that xarray.Dataset.resample has many more interesting options than this function although it does not allow to specify an interval and granularity separately.
